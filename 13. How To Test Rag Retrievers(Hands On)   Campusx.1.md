### Prerequisites
- Basic understanding of RAG (Retrieval-Augmented Generation) architecture
- Familiarity with LangChain, vector databases (Chroma), and embeddings
- Basic Python programming
- Awareness of concepts like "reference-based" vs "reference-free" evaluation (covered in the previous lecture)

### Why This Matters
In real-world ML/LLM engineering, you never build an entire application and *then* test it — like traditional software development, you build **one module → test it → build next module → test it**. Applying this to RAG:
1. Build Retriever → Evaluate Retriever
2. Build Generator → Evaluate Generator
3. Build full Pipeline → Evaluate Pipeline
4. Complete Application → Evaluate Application

All these evaluation pipelines together form the **Eval Suite**, which is later reused for **Regression Testing** (making sure new changes don't break existing functionality).

## 🔍 Understanding the Retriever

> **Definition:** A **Retriever** is a component that takes a **query** as input, converts it into a **vector embedding**, searches a **vector database** for the nearest matching vectors (chunks), and returns them as **context**.

### How it works (conceptually):

```
Query → Embedding Model → Query Vector
                              ↓
                    Search Vector Database
                              ↓
              Fetch Top-K Nearest Chunks (Context)
```

This context is later passed to the **Generator**, which uses it to produce the final answer.

## 💻 Building the Retriever - Full Code Walkthrough

The file `src/retriever.py` implements the full pipeline: **Load → Chunk → Embed → Store → Retrieve**.

```python
# ---- Imports ----
import os
from dotenv import load_dotenv                       # To load API keys from .env
from langchain_openai import OpenAIEmbeddings          # OpenAI embedding model
from langchain_chroma import Chroma                    # Chroma vector database
from langchain.docstore.document import Document       # LangChain Document object
from langchain.text_splitter import RecursiveCharacterTextSplitter  # For chunking

load_dotenv()  # Loads OPENAI_API_KEY from .env into environment variables

# ---- Configuration ----
DATA_DIR = "data"              # Folder containing transcript .txt files
DB_DIR = "chroma_store"        # Folder where the vector database will be stored


# ---- Step 1: Load Transcripts as Documents ----
def load_transcripts():
    """
    Reads all .txt transcript files from DATA_DIR.
    Removes timestamp lines (subtitle-style) and keeps only spoken text.
    Also tags each line with its session number as metadata (for citations later).
    """
    documents = []
    for filename in os.listdir(DATA_DIR):
        if filename.endswith(".txt"):
            session_id = filename  # used as metadata for citation
            with open(os.path.join(DATA_DIR, filename), "r", encoding="utf-8") as f:
                text = ""
                for line in f:
                    if not is_timestamp(line):     # skip timestamp lines
                        text += line
                documents.append(
                    Document(page_content=text, metadata={"session": session_id})
                )
    return documents


# ---- Step 2: Load or Create Vector Store ----
def load_store():
    """
    Checks if a Chroma vector database already exists.
    If yes -> loads it directly (no re-embedding, saves cost & time).
    If no  -> loads transcripts, chunks them, embeds them, and creates a new store.
    """
    embedding_model = OpenAIEmbeddings(model="text-embedding-3-small")

    if os.path.exists(DB_DIR):
        # Vector DB already exists — just load it
        return Chroma(persist_directory=DB_DIR, embedding_function=embedding_model)

    # Vector DB does NOT exist — build it fresh
    documents = load_transcripts()

    splitter = RecursiveCharacterTextSplitter(
        chunk_size=750,      # each chunk ~750 characters
        chunk_overlap=100    # 100 characters overlap between chunks (preserves context continuity)
    )
    chunks = splitter.split_documents(documents)

    # Create vector store from chunks + embeddings
    vector_store = Chroma.from_documents(
        documents=chunks,
        embedding=embedding_model,
        persist_directory=DB_DIR
    )
    return vector_store


# ---- Step 3: Build Retriever Object ----
def build_retriever():
    """
    Builds a retriever object from the vector store.
    k=5 means: fetch the top 5 nearest chunks for any query.
    """
    vector_store = load_store()
    retriever = vector_store.as_retriever(search_kwargs={"k": 5})
    return retriever


# ---- Step 4: Run a Test Query ----
if __name__ == "__main__":
    retriever = build_retriever()
    query = "What is regression testing?"
    results = retriever.invoke(query)

    for i, doc in enumerate(results):
        print(f"--- Chunk {i+1} ---")
        print(doc.page_content)
        print("Session:", doc.metadata.get("session"))
```
