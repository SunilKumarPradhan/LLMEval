## Core Concept: Online vs Offline RAG Evaluation

This is the central technical theme implied by the video's title, and understanding this distinction is critical.

| Aspect | Offline Evaluation | Online Evaluation |
|---|---|---|
| **When it happens** | Before deployment, during development | After deployment, in production, on live traffic |
| **Data used** | Curated/synthetic test datasets, golden Q&A pairs | Real user queries and real-time interactions |
| **Goal** | Validate system before shipping | Continuously monitor and catch drift/degradation |
| **Tools** | RAGAS, DeepEval, custom scripts, notebooks | LangSmith, Arize, WhyLabs, custom dashboards |
| **Feedback speed** | Slow (batch runs) | Fast / continuous (near real-time) |
| **Metrics style** | Deterministic — compared against ground truth | Often reference-free (no ground truth available) since real user questions have no pre-written "correct answer" |
| **Human involvement** | Annotators create test sets upfront | Feedback captured via thumbs up/down, user corrections, implicit signals (did user rephrase query? did user leave?) |

> 💡 **Definition — Online Evaluation:** Evaluating an LLM/RAG system's real outputs on real production traffic, typically without ground-truth labels, using techniques like LLM-as-judge, user feedback signals, and automated heuristics — done continuously, not just once.

### Why You Can't Rely on Offline Eval Alone
- Your offline test set can never cover **every real-world query pattern** users will actually throw at the system.
- Data drifts: new documents get added to your knowledge base, old ones become outdated, user intent shifts over time (seasonality, new products, new terminology).
- Model updates (e.g., swapping GPT-4 for a newer version, or updating embedding models) can silently change behavior — only caught via ongoing monitoring.
- Production has real-world constraints — latency, cost, rate limits — that don't show up in offline notebooks.

## Why Online Evaluation Matters in Production

Real-world analogy: Think of offline evaluation like a **student practicing sample papers before an exam** — useful, but the real exam (production traffic) always has some surprises. Online evaluation is like having a **teacher continuously observing the student in real exams**, catching mistakes live, and helping them improve on the fly.

**Industry use cases:**
- **Customer support RAG bots**: Monitor for hallucinated policy answers that could create legal/compliance risk.
- **Internal knowledge assistants** (e.g., for engineering docs): Detect when the retriever starts returning stale documentation after a system update.
- **Healthcare/Legal LLM apps**: Continuous monitoring is often a **regulatory necessity**, not optional — need audit trails of what was answered and how confident/faithful it was.
- **E-commerce chat assistants**: Track when answer relevancy drops during a big sale event due to sudden shifts in query patterns.
