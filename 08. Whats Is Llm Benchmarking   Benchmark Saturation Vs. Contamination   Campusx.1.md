<a name="definition"></a>
## 🔑 What is an LLM Benchmark?

> **Simple Definition:** एक Benchmark basically एक Standardized Test होता है जो किसी मॉडल की कोई specific capability को test करता है।

**Real-world analogy:** Jaise school mein different subjects (Maths, Science, English) ke standardized exams hote hain jo har student ko same conditions mein diye jaate hain taaki fair comparison ho sake — waise hi LLM benchmarks har model ko same test, same conditions mein daal ke unki capability compare karte hain.

**Industry use case:** Jab bhi koi naya model launch hota hai (GPT, Claude, Gemini, Llama, etc.), companies apne model ko multiple benchmarks pe test karke result publish karti hain taaki users/developers ko pata chale ki model kis cheez mein strong hai (coding, maths, reasoning, general knowledge, etc.)

<a name="gsm8k"></a>
## 📊 Case Study: GSM8K Benchmark

### Introduction
- **Full Form:** Grade School Mathematics 8K
- **Origin:** ~2020-2021, ab utna zyada use nahi hota (purana benchmark hai, is course mein sirf concept samjhaane ke liye liya gaya)
- **8K** = dataset mein ~8000-8500 rows (question-answer pairs)
- Available on: **Hugging Face**, **Kaggle**, direct Google search

### Component 1: Dataset / Task

> Dataset = Questions + Golden Answers (dono hote hain)

**Sample Question:**
> "Natalia sold clips to 48 friends in April and then she sold half as many clips in May. How many clips did she sell altogether?"

**Solution logic:**
- April = 48 clips
- May = 48/2 = 24 clips (half)
- Total = 48 + 24 = **72**

**Task Definition:** Jab model ko ek grade-school maths problem di jaaye, usse correct numerical answer generate karna hai.

📌 Har benchmark ka apna dedicated dataset hota hai (MMLU ka alag, SWE-Bench ka alag) — sabme common pattern: **Question + Answer pairs**.

---

### Component 2: Run Configuration

Yeh ensure karta hai ki **do models ko compare karte waqt dono ko EXACT SAME settings** mein evaluate kiya jaaye — fair comparison ke liye. Isme 3 parts hote hain:

#### (a) Prompt Construction

| Setting | Options | GSM8K mein kya hai |
|---------|---------|---------------------|
| Shot type | Zero-shot vs Few-shot | **8-shot** (few-shot) |
| Reasoning style | Direct answer vs Chain-of-Thought | **Chain-of-Thought allowed** |

> **Zero-shot:** Sirf question diya jaata hai, koi solved example nahi.
> **Few-shot:** Question ke saath pehle kuch solved examples bhi dikhaye jaate hain (context ke roop mein).

- GSM8K classically **8-shot** reported hota hai — matlab model ko question bhejne se pehle 8 solved examples system prompt mein diye jaate hain.
- **Chain-of-Thought (CoT):** Model ko step-by-step sochne ko kaha jaata hai (jaise: "48/2 = 24, phir 48+24 = 72") instead of directly answer bolne ko. CoT allow karne se accuracy improve hoti hai.

> ⚠️ Zero-shot rakhoge toh performance kam hoga, few-shot rakhoge toh performance improve hoga — GSM8K few-shot use karta hai.

#### (b) Decoding & Sampling Configuration

| Parameter | Typical Value | Reason |
|-----------|---------------|--------|
| Temperature | ~0 (zero ke aas-paas) | Zyada temperature = creative/random answers, benchmark ke liye deterministic output chahiye |
| Max Tokens | Fixed for all models | Bahut kam → CoT beech mein cut sकता है (incomplete answer). Bahut zyada → strong model bahut zyada reason kar sakta hai (unfair comparison) |

#### (c) Tooling / Environment

- Kya model ko external tools use karne ki permission hai? (Web search, Code interpreter, GitHub access, etc.)
- **GSM8K:** Tools **NOT allowed**
- **SWE-Bench** (software engineering, GitHub issues solve karna): Tools **allowed** (kyunki GitHub se issues fetch karne padte hain)

> Agar tool allow kar diya (jaise web search ya code interpreter), toh model asaani se answer nikaal lega — is se fair comparison nahi ho payega, isliye pehle se decide karna padta hai.

### Component 3: Scoring Method

Do steps hote hain:

**Step 1: Extraction**
LLM ka raw output kisi bhi format mein aa sakta hai:
- "The answer is 72"
- "72"
- "Answer: 72"

Isliye pehle correct answer ko **extract** karna padta hai. Methods:
- **Structured output enforcement** (LLM ko force karna specific format mein reply karne ke liye)
- **Regex** (pattern matching se number nikaalna)

**Step 2: Comparison**

| Answer Type | Comparison Method |
|-------------|-------------------|
| Closed-ended (jaise "72") | Programmatic exact match (72 == 72 → 1, else 0) |
| Open-ended (paragraph answer) | LLM-as-a-Judge / Human evaluation |

### Scoring Strategies (Important!)

| Strategy | Meaning | Strictness |
|----------|---------|------------|
| **pass@1** | Model se ek baar question poocha, ek baar answer liya — sahi ya galat | Strict |
| **pass@k** | Model se same question k baar poocha; agar k mein se kam se kam ek baar bhi sahi aaya toh "correct" maana jaata hai | Lenient |
| **majority@k** | Model se k baar same question poocha, jo answer sabse zyada baar repeat hua (mode), usko final answer maana jaata hai | Consensus-based |

> 💡 **Important Insight:** Jab koi bole "Mera model is benchmark pe 82% score kar raha hai" — turant poocho: **pass@1 use hua ya pass@k ya majority@k?** Kyunki different strategies se numbers bahut alag aa sakte hain, aur ye comparison ko misleading bana sakta hai.

GSM8K mein exact strategy paper dekh ke confirm karni padegi, but generally simpler benchmarks pass@1 use karte hain.
