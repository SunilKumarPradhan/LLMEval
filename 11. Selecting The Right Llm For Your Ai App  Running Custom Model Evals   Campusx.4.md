## 🎯 Step 8: Picking Candidate Models

A file called **`model_openrouter_slug.py`** was created containing a **list of tuples**, where each tuple has:
- The model's display name
- The model's **OpenRouter slug** (needed to make the API call correctly)

### Example structure:
```python

CANDIDATE_MODELS = [
    ("GPT-5.6-turbo", "openai/gpt-5.6-turbo"),      # placeholder slug format
    ("Kimi K3", "moonshotai/kimi-k3"),
    ("Grok 4.5", "x-ai/grok-4.5"),
    ("Claude Sonnet 5", "anthropic/claude-sonnet-5"),
    ("MiniMax", "minimax/minimax-latest"),
]
```

> ⚠️ **Note on slugs:** The transcript shows the instructor manually going to OpenRouter's website, searching each model by name, and copying its **exact official slug** — because OpenRouter requires the **exact slug string** to route the API call to the correct model. This list acts like a **"model database"** for the pipeline.

### Why 5 models specifically?
No fixed rule — this is a business/practical decision. If you wanted to test 10 models, you'd add 10 tuples. The number of candidates depends on:
- Budget for API testing
- Time available
- How many "serious" contenders exist for your use case
