## 🧪 What are Offline Evals? {#offline-evals}

> **Definition:** Offline Eval woh evaluation hai jo aap apni LLM-based application par **deploy karne se pehle** run karte ho, taaki yeh confirm ho sake ki application deploy karne layak hai ya nahi.

**Good news:** Ismein kuch bhi naya nahi hai! Jo bhi aapne pichle 2-3 sessions mein pipeline banana seekha (jaise UPSC mock-test grader example — golden dataset banana, LLM-as-a-judge use karna, evaluation perform karna), **woh sab offline eval ka hi example hai**.

### 🔑 Core Idea

```
Software Build → [OFFLINE EVAL happens here] → Deployment → Production
```

- Software banne ke baad
- Deployment hone se **pehle**
- Golden dataset ke against test karna

**Simple language mein:** Jab aap apne LLM application ko deploy karne se pehle poori tarah test karna chahte ho ki woh deploy karne layak hai ya nahi — wahan jo evals chalate ho, unhe **Offline Eval** bolte hain.

## ✅ Benefits of Offline Evals {#benefits-offline}

### 1️⃣ Pre-Release Testing (Release Gate)

Bina test kiye software ko production mein daalna risky hai — aapko pata nahi chalega ki wo production mein kaisa behave karega.

**Real-world automation (CI/CD):**

```
Code Change → Git Push → CI Triggered (GitHub Actions) 
     → Eval Script Runs → Score Generated
          ├── Score ≥ Threshold (e.g. 95%) → Auto Deploy ✅
          └── Score < Threshold → Notification/Rollback ❌
```

- Isse aap ek **"gate"** bana sakte ho — agar eval score threshold se upar hai to hi deployment pipeline trigger hogi
- Agar score kam hai, toh notification aa jayega ki eval test fail ho gaye, aur system previous stable version pe rollback kar sakta hai
- Yeh concept aage "LLM Ops" course mein detail se cover hoga

### 2️⃣ Version Comparison

Jab aapke paas multiple choices hon (e.g., **Claude model vs OpenAI model** for UPSC grading app), toh confusion hota hai ki kaunsa better hai.

**Solution:**
- Do versions banao apne software ke (Version A: Claude-based, Version B: OpenAI-based)
- Dono par **same eval** aur **same golden dataset** run karo
- Chunki dono ke liye field level hai (everything else same, sirf model different), results directly compare kar sakte ho
- Jo version zyada score kare, use choose karo

Yeh comparison sirf models ke liye nahi, balki in sab ke liye kar sakte ho:
- Different **prompts**
- Different **models**
- Different **re-rankers**
- Different **vector databases**
- Different **architectures** of the application

> Jab bhi confusion ho "Which one should I choose?" — offline eval multiple versions pe run karke yeh decide karta hai.

### 3️⃣ Regression Testing

> **Definition (Regression Testing):** "Test of change" — jab aap software mein ek cheez improve karte ho, toh yeh check karna ki kahin usse doosri cheez kharab toh nahi ho gayi.

**Example (CampusX Chatbot):**
1. Production mein observe kiya ki chatbot refund-related questions par "cold" tone mein reply karta hai
2. System prompt mein change kiya: "You have to be very kind and polite"
3. Result: Chatbot ka tone bahut zyada soft ho gaya — jaise cost bataate waqt exact number (19,500) na bolke approximate ("around 19,000") bolne laga sirf "impress" karne ke liye
4. Yeh ek unintended side-effect hai — isko hi **Regression** bolte hain

**Kaise offline eval yeh detect karta hai:**
- Golden dataset mein different categories ke test cases daalo (refund questions, pricing questions, curriculum questions, etc.)
- Har category pe pehle se success rate track karo (e.g., Refund questions: 90% success)
- Change karne ke baad wahi category dobara test karo
- Agar score 90% se gir kar 80% ho jaye → **Regression detected**, is change ko revert karna chahiye

> **Rule:** Jab bhi koi small change karo (system prompt, model, vector database, kuch bhi) — check karo ki usse kuch aur toh nahi bigda.

### 📋 Summary of Offline Eval Benefits

| Benefit | Kya karta hai |
|---------|---------------|
| Pre-release Testing | Deployment se pehle software test karna, CI/CD gate ki tarah kaam karna |
| Version Comparison | Multiple models/prompts/architectures ko compare karna |
| Regression Testing | Changes karne ke baad existing functionality kharab na ho, yeh verify karna |

## ⚠️ Production Risks After Deployment {#production-risks}

Software deploy ho gaya, offline eval bhi pass ho gaya... **par ab kya?** Production mein 3 major risks aati hain:

### 1️⃣ Unanticipated Inputs

Offline testing mein golden dataset mein sirf 200-500 anticipated questions daale gaye the. Lekin production mein real users kuch bhi puch sakte hain:

- **Hindi-English mixed** language questions (agar model mostly English pe train/tuned tha)
- **Ambiguous/half-questions** jinka matlab samajhna mushkil ho
- **Angry rants** jinke peeche ek chhupa hua question ho
- **Adversarial prompt injections** — jahan users chatbot se aisa answer nikalwane ki koshish karte hain jo usko nahi dena chahiye
- Bahut saare **edge cases** jo anticipate hi nahi kiye the

> Golden dataset ek **subset** hai; real-world input space uska **superset** hai jisme kuch bhi ho sakta hai.

### 2️⃣ Emergent & Systematic Failures

Chhote-chhote failures jo sirf **scale par** dikhte hain, offline setup mein nahi:

- **Latency issues:** Concurrent hazaaron users aane par response time badh jaata hai — isko offline test nahi kar sakte kyunki wahan itne users simulate nahi kar sakte
- **Subtle Bias:** Model non-technical background wale users ke saath thoda bias-ed behavior kar sakta hai. Yeh pattern sirf tabhi dikhega jab thousands of conversations ka data collect hoga

### 3️⃣ Drift

> **Definition:** Drift matlab time ke saath aapka offline eval setup (golden dataset) **obsolete** ho jaana kyunki underlying data/business changes ho chuki hai.

**Example:**
- Aaj CampusX chatbot banaya — sab documents (pricing, curriculum, policies) current hain
- 1 saal baad: course prices change, curriculum update, policies change
- Golden dataset abhi bhi 1 saal purane data ke hisaab se hai
- Offline eval abhi bhi "achhe results" dega (kyunki wo purane data se compare kar raha hai)
- Lekin real users se **negative feedback** aayega kyunki chatbot outdated information de raha hai
- **Root cause:** Business data change ho raha hai, par eval setup update nahi ho raha

### 🎯 Summary of Production Risks

| Risk | Description | Detectable Offline? |
|------|-------------|---------------------|
| Unanticipated Inputs | Real users kuch bhi pooch sakte hain (mixed language, ambiguous, adversarial) | ❌ No |
| Emergent/Systematic Failures | Scale-related issues (latency, bias) jo sirf bade data pe dikhte hain | ❌ No |
| Drift | Golden dataset/eval setup obsolete ho jaana as business/data changes | ❌ No |

> **Conclusion:** Offline eval sirf golden dataset ke against test karta hai. Production mein na golden dataset hai, na correct answers pata hain future
