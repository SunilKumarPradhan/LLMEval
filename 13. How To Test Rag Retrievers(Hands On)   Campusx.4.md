## 🐍 Fixing the ModuleNotFoundError — Python Package Basics {#module-error}

### The Problem

While trying to run the evaluation script (`eval_retriever.py`) which imports code from a `src` folder (like `retriever.py`), Python throws:

```
ModuleNotFoundError: No module named 'src'
```

> **Definition:** `ModuleNotFoundError` occurs when Python's import system cannot locate the module you're trying to import, based on the current working directory and Python's module search path (`sys.path`).

### Why This Happens

Project folder structure looked like this:

```
project/
├── src/
│   └── retriever.py
└── evals/
    └── eval_retriever.py
```

When you run:
```bash
python eval_retriever.py
```
...from **inside** the `evals/` folder, Python treats the current directory as the "root" for imports. Since `evals/` doesn't contain a `src/` folder inside it, Python can't find `src`, even though `src` exists as a sibling folder at the project root.

> In short: **Python looks for modules relative to how the script is run, not relative to where the file "logically" lives.**

### The Fix — Convert Folders into Python Packages

**Step 1:** Add an `__init__.py` file inside both folders to mark them as **Python packages**.

```
project/
├── src/
│   ├── __init__.py      # 👈 makes src a package
│   └── retriever.py
└── evals/
    ├── __init__.py      # 👈 makes evals a package
    └── eval_retriever.py
```

> **Definition:** An `__init__.py` file (even if empty) tells Python "treat this folder as a package," enabling relative and absolute imports across folders in a project.

**Step 2:** Run the script **as a module**, from the **project root** (one level above both `src` and `evals`), using the `-m` flag:

```bash
python3 -m evals.eval_retriever
```

### Line-by-Line Breakdown

```python
python3 -m evals.eval_retriever
```

| Part | Meaning |
|------|---------|
| `python3` | Invokes the Python 3 interpreter |
| `-m` | Tells Python to run a **module** by its dotted import path, not as a standalone script |
| `evals.eval_retriever` | Dotted path meaning: "go into the `evals` package, find `eval_retriever.py`" |

**Why `-m` fixes the issue:** When you use `-m`, Python adds the **current working directory (project root)** to `sys.path`, instead of adding the script's own folder. This means both `src` and `evals` — being siblings at the root — become visible/importable.

```python
# Comparison
python eval_retriever.py          # ❌ runs as a script; sys.path[0] = evals/ folder → src not visible
python3 -m evals.eval_retriever   # ✅ runs as a module; sys.path[0] = project root → src visible
```

> ⚠️ **Common Mistake:** Beginners often try to fix `ModuleNotFoundError` by messing with `sys.path.append()` hacks inside code. The cleaner, standard fix is: (1) add `__init__.py`, (2) run using `-m` from the project root.

### Initial (Baseline) Run Output

| Metric | Score |
|--------|-------|
| Contextual Recall | 80% |
| Contextual Precision | 80% |
| Test Cases Passed | 10 / 15 |
| Test Cases Failed | 5 / 15 |

> **Definition (recap):**
> - **Contextual Recall** — measures whether all the *relevant* information needed to answer the question was retrieved (did we miss anything important?).
> - **Contextual Precision** — measures how much of what was retrieved is actually *relevant and well-ranked* (how much noise/irrelevant content is in the retrieved context, and is relevant content ranked higher?).

### What To Do With Failed Test Cases

DeepEval shows a **reason** for each failure. The recommended practice:

> You should always go and **read the failure reasons for each individual test case**. Only then can you understand *what kind of mistakes* your retriever is making (e.g., missing chunks, irrelevant chunks ranked too high, wrong chunk boundaries, etc.)

This diagnostic step is what tells you **which improvement lever to pull** next.

## 🔧 Improvement Strategy 1: Tuning Chunking Parameters {#chunking}

### The Two Key Chunking Parameters

| Parameter | What it Controls |
|-----------|------------------|
| **Chunk Size** | How many characters/tokens go into each chunk of text |
| **Chunk Overlap** | How many characters overlap between consecutive chunks (prevents context from being cut off at boundaries) |

### Baseline vs New Settings

| Setting | Old Value | New Value |
|---------|-----------|-----------|
| Chunk Size | 750 | 1000 |
| Chunk Overlap | 100 | 150 |

### Why Increase Chunk Size?

Smaller chunks can **split relevant information across boundaries**, causing the retriever to miss context (hurting recall) or retrieve incomplete/fragmented, less meaningful chunks (hurting precision). Larger chunks preserve more coherent context per chunk.
