<a name="reason-1"></a>
## 🧩 Reason 1: Multiple Failure Points

### 🏗️ RAG Chatbot — Basic Architecture

Let's take an example: building a **RAG (Retrieval Augmented Generation) chatbot** for a company/school/college.

**Components of a RAG system:**

```
User Query
    │
    ▼
┌─────────────┐        ┌──────────────┐
│  Retriever  │◄──────►│ Vector DB    │
└─────────────┘        └──────────────┘
    │ (relevant documents)
    ▼
┌─────────────┐
│  Generator  │  (This is an LLM)
│  (LLM)      │
└─────────────┘
    │
    ▼
Final Answer
```

**Flow:**
1. Query comes to the **Retriever**.
2. Retriever fetches **relevant documents** from the **Vector Database** based on the query.
3. Query + Retrieved Documents are passed together to the **Generator** (an LLM).
4. Generator produces the final answer based on the relevant context.

### ⚠️ Identifying Failure Points

Just by looking at this architecture, **two obvious failure points** emerge:

| Failure Point | What Can Go Wrong |
|---------------|--------------------|
| **Retriever** | Fetches wrong/irrelevant documents → generator gives wrong answer based on wrong docs |
| **Generator** | Even with correct documents, it may **hallucinate** or ignore the context and generate incorrect facts |

**Logical conclusion:** Since both components can independently fail, you need:
- One **evaluation pipeline for the Retriever**
- One **evaluation pipeline for the Generator**

### 🔍 Retriever Eval Pipeline

> **Goal:** Given a query, check whether the retriever is fetching the **right, relevant documents** from the vector database.

This quality check is often called **Context Relevance**.

### 🔍 Generator Eval Pipeline

> **Goal:** Given a context (retrieved documents), check whether the generator produces an answer **faithful** to that context.

This quality check is called **Faithfulness** (also called **Groundedness**).

**Example:**
- Question: *"What is the duration of the Machine Learning course?"*
- Retrieved document says: *"3 weeks"*
- ✅ Correct answer: *"The Machine Learning course duration is 3 weeks."*
- ❌ Wrong (ungrounded) answer: *"The ML course duration is 3 weeks. It's a great course! You can also purchase the Python course, which is 4 weeks."*

The additional information (course being "great", mentioning Python course) is **not grounded** in the given context — this is a faithfulness violation, even though it might sound helpful.

> **Faithfulness/Groundedness:** The answer must be strictly based on the given context — no self-generated/extra facts should be added.

### 🔬 Deep Dive: The K-Parameter Problem (Why Component-Level Evals Aren't Enough)

This is the **key intuitive example** of the lecture, demonstrating that even if both Retriever and Generator individually pass their evals, the **combined pipeline can still fail**.

**What is K in a retriever?**

> **K** in RAG retrieval means: the number of top relevant documents to fetch from the vector database. E.g., K=5 means fetch the **top 5 most relevant documents**.

**Scenario:**

- User asks: *"What is the duration of the Machine Learning course?"*
- Retriever is set with **K = 5**
- It fetches 5 documents:

| Doc | Content |
|-----|---------|
| D1 | Some random thing |
| D2 | Some random thing |
| D3 | Some random thing |
| D4 | Some random thing |
| D5 | "The duration of ML course is **8 weeks**" (correct answer!) |

**Question: Did the Retriever do its job correctly?**

✅ **YES.** Since K=5
