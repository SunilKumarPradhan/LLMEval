## 🧭 Overview

यह भाग (Part 3) उस पूरी सीरीज़ का सबसे **practical और hands-on हिस्सा** है, जहाँ theory से निकलकर हम actual implementation में जाते हैं।

**इस सेक्शन में क्या कवर होगा:**
- Leaderboard से top models को filter और rank करना (cost + coding capability + latency के आधार पर)
- Top 10 में से final 5 candidate models चुनना जिन्हें हम test करेंगे
- **Custom Model Evaluation Pipeline** को शुरू से end-to-end बनाना:
  - Dataset लाना
  - Database में load करना
  - Schema extract करना
  - Golden Dataset बनाना
  - Validation करना
  - Evaluation loop चलाना (accuracy निकालना)
- **OpenRouter** नाम के platform से सारे models को एक जगह access करना
- LangChain के साथ इसका integration

**Prerequisites (Part 1 & 2 से):**
- LLM Leaderboards को पढ़ना आना चाहिए (cost, latency, throughput, correctness metrics)
- Normalization (0 to 1 scaling) का basic ML concept
- System prompt में schema भेजने का concept
- Text-to-SQL app का use case समझना (Cricinfo जैसा app)

**यह क्यों matter करता है:**
जब आप production में LLM based app बना रहे हों (जैसे Text-to-SQL analytics tool), तो सिर्फ leaderboard के benchmark scores पर भरोसा नहीं कर सकते — आपको **अपने खुद के डेटा और task पर model को test करना पड़ता है**। यही असली "Custom Eval" है, और यही सबसे crucial decision-making step है model selection में।

## 🎯 Stage 2 (Continued): Filtering & Ranking Models from the Leaderboard

### Filtering Strategy (Step-by-Step)

```
Step 1: Cost Filter
   └── Leaderboard के सारे models में से वो हटाओ जो
       ₹5 lakh/month से ज्यादा खर्चा दे रहे हैं

Step 2: Remaining models पर Ranking बनाओ
   └── दो factors के आधार पर:
       (a) Coding Capability (Correctness)
       (b) Latency / Throughput (characters per second)

Step 3: दोनों factors को Normalize करो (0 to 1 range में)

Step 4: दोनों को Weightage दो और Combine करके एक Final Score बनाओ

Step 5: Final Score के हिसाब से Sort करो → Top 10 models मिल गए
```

### इस Application में Latency क्यों कम matter करती है?

> इस particular use case (Text-to-SQL for Cricinfo) में LLM को सिर्फ एक **SQL query** generate करनी है — जो कि एक बहुत छोटी string होती है (शायद 50-200 characters)। चाहे model slow हो या fast, 100 characters print करने में ज्यादा time का फर्क नहीं पड़ेगा।

इसलिए:
- **Coding Capability को Weightage = 9** (ज्यादा important — क्योंकि गलत SQL से गलत answer मिलेगा)
- **Latency को Weightage = 1** (कम important — क्योंकि output छोटा है)
