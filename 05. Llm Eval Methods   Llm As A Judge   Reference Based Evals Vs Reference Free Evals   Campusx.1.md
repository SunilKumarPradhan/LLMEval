## 🧩 What is an LLM Eval Method?

> **Definition:** An LLM eval method is the mechanism you use to decide whether an LLM's output is good or not — the actual procedure that takes an output and produces a judgment about it.

Simple shabdon mein: Eval pipeline banane ke baad, us pipeline ko **execute kaun karega** — yahi cheez "eval method" decide karta hai.

**Evaluation pipeline banane ka purpose:**
Taaki hum pata laga sakein ki hamara koi component, workflow, ya poora application sahi se kaam kar raha hai ya nahi.

## 🎯 The Three Core Eval Methods

Koi bhi evaluation pipeline banaoge, usme **teen mein se koi ek** hi method hoga:

1. **Programmatic / Deterministic Method** — Ek program/code execute karta hai eval ko
2. **Human Method** — Ek insaan (human) eval carry out karta hai
3. **Model-Graded / LLM-Graded Method** — Khud ek LLM eval carry out karta hai (aage padhenge is part mein detail se nahi)

```
Evaluation Pipeline
        │
        ├── Programmatic (Code/Program executes)
        ├── Human (Insaan executes)
        └── Model-Graded (LLM executes)
```

## ⚙️ Method 1: Programmatic / Deterministic Evaluation

> **Definition:** Jab poora evaluation ek code/program ke through automatically execute hota hai, bina kisi human ya LLM ki judgment ke.

### 📌 Case Study: Evaluating a RAG Chatbot's Retriever

**Scenario:** CampusX ke liye ek RAG chatbot banaya gaya hai jisse users interact kar sakein aur unhe help mile — manually email reply karne ki zaroorat na pade. Is chatbot ko achhe se banane ke liye **har component ka eval pipeline** banaya jaayega. Sabse pehle **Retriever** component pakड़ते hain.

**Retriever ka kaam:** Jab koi question aata hai, retriever vector database mein se sabse relevant documents dhoondh kar laata hai.

#### Step-by-Step Eval Pipeline Design (Retriever)

**Step 1: Task & Target Define karo**
- Task: Retriever sahi se kaam kare
- Target: Single component — Retriever

**Step 2: Success Criteria Define karo**

> **Metric: Recall@k**
> "Out of all the correct items that exist, how many did the system retrieve in its top-k results?"

**Example Calculation:**

Question: *"What are the prerequisites for ML course and how long is it?"*

- Correct (relevant) documents already known (from golden dataset): **1001, 1003**
- Retriever asked to fetch k=5 documents
- Retriever returns: **1001, 1002, 1004, 1005, 1006**

Calculation:
- Total correct documents that existed = 2 (1001, 1003)
- Correct documents retrieved = 1 (only 1001)
- **Recall = 1/2 = 50%**

```
Recall@k = (Number of relevant docs retrieved in top-k) / (Total relevant docs that exist)
```

- Ideal recall = 100% (max), minimum = 0%
- Other related metrics exist too: **Precision**, **Rank** — lekin abhi discussion simple rakhte hain, sirf Recall@k pe focus.

**Step 3: Build a Dataset (Golden Dataset)**

- 50-100 questions nikale gaye jo future users pooch sakte hain
- Coverage ensure kiya gaya: edge cases, difficult questions, easy questions, random questions
- Ek **human expert** ko baithaya gaya jo har question ko dekh kar vector database mein khoजता hai ki kaunsa document uska sahi answer contain karta hai
- Isse **Golden Dataset** ban gaya (Question + Correct Document IDs mapping)

> ⚠️ Note: Golden dataset banane mein human involved hota hai — lekin isse "Human Eval Method" nahi kaha jaata. Golden dataset creation ek **separate activity** hai. Eval method wo hai jo **eval ko execute, run aur score extract karta hai**.

**Step 4: Define Evaluation Method (Programmatic)**

Process:
1. Saare 50 questions retriever ko bheje jaate hain (poore RAG chatbot ko nahi, sirf retriever ko)
2. Retriever ka k = 5 set kiya gaya
3. Har question ke liye retriever apne top-5 documents return karta hai
4. Har question ke liye **row-wise / per-question Recall@k** calculate kiya jaata hai:
   - Q1: Sara info ek hi doc (1001) mein tha, retriever 1001 la paaya → Recall = 100% (1/1)
   - Q2: Correct docs the 1001 & 1003; sirf 1001 mila → Recall = 50% (1/2)
   - ... isi tarah har question ke liye
5. Final: Sab per-question recalls ka **average** liya jaata hai → overall **Recall@k** for the whole dataset

**Result in example:** Overall Recall = **67%**

**Step 5: Improve the Retriever**

Un questions ko deeply study karte hain jahan recall kam tha. Improvement options:

| Improvement Technique | Explanation |
|---|---|
| Better Embedding Model | Ho sakta hai current model semantic meaning sahi se capture nahi kar pa raha |
| Query Expansion | User query ko directly na bhej kar, pehle LLM se expand karo, phir retriever ko bhejo |
| Increase k | k=5 se k=10 try karo |
| Re-ranking | Agar doc top-10 mein tha par top-5 mein nahi, re-ranker laga kar usko upar la sakte ho |
