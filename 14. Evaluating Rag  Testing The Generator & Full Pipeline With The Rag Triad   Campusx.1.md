## 🛠️ Building the Generator Component <a name="building-generator"></a>

> **Generator**: A function that takes a **question** and **relevant documents (context)** as input, and returns a **generated answer** as output. Internally, it simply wraps an LLM call with a well-designed prompt.

### How it fits in the RAG Pipeline
```
User Query ──► Retriever ──► Top-K Relevant Docs
                                    │
                                    ▼
            Query + Relevant Docs ──► Generator ──► Answer
```

Since the Generator is "just an LLM call with a prompt," the code is simple. The instructor uses a pre-written code file from GitHub (pushed as `src/generator.py`) instead of writing from scratch, to save time.

## 💻 Generator Code Walkthrough <a name="code-walkthrough"></a>

```python
# generator.py

# 1. Import required libraries
from dotenv import load_dotenv          # to load environment variables (API keys)
from langchain_openai import ChatOpenAI  # LLM wrapper for OpenAI models
from langchain_core.prompts import ChatPromptTemplate  # to build structured prompts
from langchain_core.output_parsers import StrOutputParser  # extracts plain string from LLM response

# 2. Load environment variables (needed for OpenAI API key)
load_dotenv()

# 3. Initialize the LLM
llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
# - gpt-4o-mini: cheap and fast, good enough for this task
# - temperature=0: makes output deterministic/consistent
#   -> During EVALUATION, temperature is almost always set to 0
#      (even though this specific code is "building" the RAG generator itself)

# 4. Build the prompt template
prompt = ChatPromptTemplate.from_template("""
You are a helpful teaching assistant for a course on LLM evaluations.
Answer the student's question ONLY from the context provided below.
- Use only information present in the context.
- Do NOT add outside knowledge.
- If the context does not contain enough information to answer,
  say "I don't have enough information in the course material to answer."
- Keep the answer clear and concise.

Context: {context}
Question: {question}
""")

# 5. Build a simple LangChain chain: prompt -> LLM -> string parser
chain = prompt | llm | StrOutputParser()

# 6. Define the generate function
def generate(query: str, context: str) -> str:
    """
    Takes a query and context, returns the generated answer.
    """
    return chain.invoke({"question": query, "context": context})

# 7. Test code (dummy context, can be ignored/removed later)
if __name__ == "__main__":
    dummy_context = "Online eval means evaluating your system on live production traffic after deployment. It works without an answer key, unlike offline eval."
    question = "What is online eval?"
    answer = generate(question, dummy_context)
    print(answer)
```

### Line-by-Line Explanation

| Line/Block | Purpose |
|---|---|
| `load_dotenv()` | Loads `.env` file so `OPENAI_API_KEY` is available to the app |
| `ChatOpenAI(model="gpt-4o-mini", temperature=0)` | Creates the LLM instance; `temperature=0` removes randomness — critical for **reproducible evaluations** |
| `ChatPromptTemplate.from_template(...)` | Defines the **instructional prompt** — explicitly tells the LLM to (a) use only the given context, (b) not hallucinate, (c) admit when it doesn't know, (d) be concise |
| `prompt | llm | StrOutputParser()` | LangChain's **pipe syntax** creates a chain: prompt formats input → LLM generates response → parser extracts plain text string from the LLM's message object |
| `generate(query, context)` | The public-facing function — takes 2 inputs (query, context), returns 1 output (answer string) |
| Test block | Simulates a retriever by manually creating a dummy context — this is NOT a real retriever call, just to test the generator function works |

### Why `temperature=0` for Evaluation?
> Evaluation demands **consistency and reproducibility**. A high temperature introduces randomness, making it hard to trust whether a low/high score is due to genuine quality issues or random variation.

### Running the Code
When executed, the generator successfully answered "What is online eval?" using only the dummy context provided — proving the **code works mechanically**. However:

> ⚠️ **Important distinction**: Running the code successfully only proves it's *functional*, NOT that it's *producing good/accurate answers*. Quality is determined only through **evaluation** — which is the next step.

## ⚠️ Failure Modes of a Generator <a name="failure-modes"></a>

**First-principles approach to evaluation**: Before evaluating any system, ask — *"In how many ways can this system fail?"* Then build metrics to detect exactly those failures.

The Generator has **two major failure modes**:

### 1️⃣ Unfaithful Response (Hallucination)

> **Unfaithful Response**: When the generator adds information NOT present in the given context — essentially "inventing" facts on its own instead of strictly using the provided context.

**Example:**
- **Question**: "Does the CampusX AI Engineering program include live classes?"
- **Context provided**: "The AI Engineering program includes recorded lessons, coding assignments, projects, and weekly doubt-solving sessions." (No mention of live classes at all!)
- **Generated Answer**: "Yes. The program includes two live classes every week along with weekly doubt-solving sessions."
- **Verdict**: ❌ **NOT faithful** — the LLM hallucinated the "two live classes" detail; it doesn't exist in the context.

> 🚨 **Real-world danger**: This is exactly what happened in the famous **Air Canada chatbot case** — the bot told a customer they could book a ticket and get reimbursed later, information that wasn't in its actual policy context. This was a **Generator failure** (unfaithfulness), and it led to real legal/financial consequences for the airline.

### 2️⃣ Answer Irrelevance

> Even when the generator is 100% faithful to context (doesn't hallucinate), the generated answer might still **fail to actually answer the user's question**.

**Example:**
- **Question**: "Does the CampusX AI Engineering program include live classes?"
- **Context**: "The program includes coding assignments, projects, recorded lessons and weekly doubt-solving sessions."
- **Generated Answer**: "The program includes coding assignments, projects, recorded lessons and weekly doubt-solving sessions."
- **Faithful?** ✅ Yes — every word comes straight from context.
- **Relevant?** ❌ No — it never actually answers whether live classes exist!
- **Ideal Answer**: "The provided context does not confirm that the program includes live classes. It only mentions recorded lessons, coding assignments, projects, and weekly doubt-solving sessions." — This is BOTH faithful AND relevant.
