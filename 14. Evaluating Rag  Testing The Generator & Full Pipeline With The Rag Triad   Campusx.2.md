## 🧩 Understanding Faithfulness Metric {#faithfulness}

> **Definition**: Faithfulness measures how **faithful/grounded** the generated answer is to the **provided context** — it does NOT measure whether the answer is factually "correct" in an absolute sense.

### How It Works (Claim-Based Scoring)

1. The generator's answer is broken down into individual **claims/statements** by an LLM judge.
2. Each claim is checked against the retrieved/golden **context**.
3. If a claim is supported by the context → marked faithful.
4. If a claim is NOT supported by the context → marked unfaithful.
5. **Final score = (Number of faithful claims) / (Total number of claims)**

### Example (from transcript)

Suppose for a query, the generator produces an answer containing 2 claims:
- Statement 1 → Correctly represents context (faithful) ✅
- Statement 3 → Not relevant/not supported by context ❌

```
Faithfulness Score = 1/2 = 50%
```

> ⚠️ **Important Distinction**: This is NOT about correctness. Faithfulness only checks "did the LLM stick to what the context said" — not "is this answer actually true in the real world."

### Why Faithfulness Scores Naturally Come Out High

Since the generator is **explicitly instructed** ("answer this question using ONLY this context"), and modern LLMs have **high instruction-following capability**, there's a high probability the answer will indeed be grounded in the given context. This is why Faithfulness scores are often high (90%+) even without heavy tuning.

### Aggregation Across Dataset

```
Per Question:
   Faithfulness Score = (faithful claims) / (total claims)

Across Dataset (e.g., 15 questions):
   Final Faithfulness Score = Average of all per-question Faithfulness Scores
```

> **Q&A from lecture**: "Is number of claims a hyperparameter we control?"
> **A**: No — the number of claims is decided automatically by the judge LLM during claim extraction; it's not something you manually configure.

## 🎯 Understanding Answer Relevancy Metric {#answer-relevancy}

> **Definition**: Answer Relevancy measures how **relevant** the generated answer is to the **question asked** — again, this does NOT measure correctness, just topical/semantic relevance.

### Key Difference from Faithfulness

| Aspect | Faithfulness | Answer Relevancy |
|--------|-------------|-------------------|
| Checks | Answer vs. Context | Answer vs. Question |
| Question asked | "Is this grounded in context?" | "Does this actually answer the question?" |
| Correctness? | ❌ No | ❌ No |

Correctness is a **separate metric altogether** (to be covered in a future class).

### Why Answer Relevancy Is Harder to Score High

Unlike faithfulness (where the LLM is told exactly what info to use), relevancy requires the answer to be **on-topic and directly address the user's question** — this is a more nuanced judgment, so scores tend to start lower and require more tuning (prompt engineering) to improve.
