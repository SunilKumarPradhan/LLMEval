## 💻 Capability 2: Coding {#coding}

> **Definition:** Coding capability measures whether an LLM can understand, generate, debug, and interact with code and software systems effectively.

### What Gets Tested

- Can the model **generate working code** from a natural language prompt?
- Can it **debug** broken code and fix it?
- Can it use **APIs and function calling** correctly?

### Real-World Relevance

Whenever you're building an **AI coding agent** (like GitHub Copilot, Cursor, Windsurf, Claude Code, etc.) — and there are many such tools now — this is the exact capability your LLM needs to be strong at.

```
Real-world applications:
├── AI coding assistants (Copilot, Cursor)
├── Autonomous coding agents (Devin, Claude Code)
├── Code review automation
└── API integration / function-calling systems
```

**Why it's important:** As AI coding agents become mainstream, labs must prove their models can reliably write, debug, and interact with code/APIs — this directly impacts developer adoption.

## 🔢 Capability 3: Mathematics {#mathematics}

> **Definition:** Mathematics capability measures whether a model can perform **accurate symbolic and numerical reasoning**.

### Key Insight: Math = A Form of Reasoning

Maths is essentially reasoning where you move **step-by-step** toward a solution. It's a subtype of reasoning, but it has **far more direct real-world applications** than general reasoning, which is why it gets its own dedicated capability and benchmark category.

### Levels of Math Tested (Easy → Hard)

| Level | Description |
|-------|-------------|
| **Grade School** | 7th–8th grade level math problems |
| **Competition Level** | Olympiad-style problems requiring creative thinking |
| **Undergraduate Level** | College-level math problems |
| **Research Level** | Open-ended problems with **no known solution yet** |

### Real-World Applications

- 🔬 Scientific computing
- 💰 Financial modeling
- ⚙️ Engineering simulations
- 📊 Data analysis

**Why it's important:** Because so many high-value fields depend on mathematical accuracy, this capability has a large number of dedicated benchmarks built around it.

## 📏 Capability 4: Long Context {#long-context}

> **Definition:** Long Context measures whether a model can **effectively use information from very long inputs** — sometimes containing hundreds of thousands of tokens — not just whether it can technically "accept" that many tokens.

### The Core Problem

Modern models advertise **huge context windows** (128K, 200K, even 1 million tokens). But there's a big difference between:
- **Context window size** (how many tokens the model *can accept*)
- **Effective context usage** (how well the model *actually uses* that information)

> ⚠️ **Real observation:** As a chat conversation grows longer, the model's ability to retain context **diminishes over time**, and response quality degrades — even if the "limit" hasn't been reached.

### What Gets Tested

1. **Needle-in-a-haystack**: Can it extract a small fact from a very long context?
2. **Entity retrieval**: Can it fetch details about a specific person/entity from a huge document?
3. **Summarization**: Can it summarize very long context accurately?
4. **Codebase context**: Can it maintain context of an entire large codebase (relevant for coding agents)?

### Why It's Critical for Frontier Labs

Labs claim large context windows as a marketing point, but **actual retention quality** is what benchmarks reveal. This tells you which model *genuinely* performs well on large context vs. which one just *accepts* large context without using it well.

**Real-world relevance:** Any LLM application you build will need to handle context — this capability directly tells you how much context is *actually usable*, not just theoretically supported.

## 🖼️ Capability 5: Vision & Multimodal {#vision-multimodal}

> **Definition:** This capability tests whether a model goes **beyond text** — can it understand images, videos, and other modalities?

### What Gets Tested
- Understanding of **images**
- Understanding of **video**
- General **multimodal comprehension**

### Why It's Important

We live in a **multimodal world**, not a text-only world. Real examples:
- 📱 Turning on your phone camera and asking "What can I cook with what's in my fridge?"
- 📚 Asking about a specific book by showing a picture of a library shelf

Since real-world use cases constantly involve non-text inputs, dedicated benchmarks are needed to measure multimodal capability — text-only evals are insufficient.

## 🤖 Capability 6: Agentic & Tool Use {#agentic-tool-use}

> **Definition:** Measures how effectively a model can use **external tools** to actually *do* things, not just generate text.

### The Big Shift

The entire field of **Agentic AI** emerged from this need:
> "You don't just need an LLM that prints text. You need an LLM that can *act*."

To act, models need **tools attached** to them.

### What Gets Tested

- Can the model do **web browsing** on its own?
- Can it perform **structured tool calling**?
- Can it **interact with APIs**?
- Can it use **desktop/computer interfaces** (computer-use capability)?

### Real-World Relevance

As more **agentic applications** emerge (autonomous agents that browse, book, code, research, etc.), companies need a **reliable model** that can be trusted to perform agentic tasks correctly. These benchmarks tell you exactly that.

## 🛡️ Capability 7: Safety & Alignment {#safety-alignment}

> **Definition:** Measures whether a model can be **trusted to behave responsibly**.

### What Gets Tested

| Check | Description |
|-------|-------------|
| **Harmful content** | Does the model avoid generating harmful content? |
| **Adversarial robustness** | Is it easy to "jailbreak" or attack the model with adversarial prompts? |
| **Truthfulness vs. Sycophancy** | Is the model honest, or does it flatter the user? |
| **Cybersecurity skills** | Can it do cryptography, reverse engineering, digital forensics? |

### Truthful vs. Sycophantic Models

> **Sycophancy** = when a model excessively agrees with / flatters the user instead of giving honest feedback.

- 🗣️ Example given: ChatGPT tends to praise ideas immediately ("Yes, this is the best idea in the world!") — this is **sycophantic** behavior.
- 🗣️ Claude, in the speaker's personal experience, is **more truthful** — it points out flaws ("There's a flaw in what you said").
- Ideally, a model should be **truthful**, not sycophantic.

### Cybersecurity as an Emerging Safety Concern

Recently, benchmarks have emerged to test whether models have dangerous/useful cybersecurity skills:
- Cryptography
- Reverse engineering
- Digital forensics

**Example mentioned:** Anthropic's **Claude "Fable"** model was noted to be extremely strong in cybersecurity and reportedly found many vulnerabilities in existing software — showcasing why this needs dedicated evaluation.

### Why Safety Matters So Much to Frontier Labs

1. **Government/regulatory pressure** — governments push labs to ensure model safety.
2. **Reputational risk** — a single safety incident can severely damage a company's business ("their entire business could shut down").

## 📝 Capability 8: Instruction Following {#instruction-following}

> **Definition:** Measures whether the model follows the user's instructions **exactly as specified** — not just approximately.

This is a somewhat **underrated but very important** capability.

### What Gets Tested

- If asked for a **bullet list**, does the model respond in bullet list format?
- If asked for **under 200 words**, does it stay within that limit?
- If asked for a **friendly tone**, does it maintain that tone?
- If given **ambiguous instructions**, does the model ask **clarifying questions** instead of guessing?

### Why It's Critical

> This directly translates into **user feedback and product retention**.

If a model doesn't follow instructions:
- User becomes unhappy
- User abandons the product
- User switches to a competitor

**Business impact:** Instruction-following capability directly affects user satisfaction and retention — making it a high-stakes capability despite being less "glamorous" than coding or math.
