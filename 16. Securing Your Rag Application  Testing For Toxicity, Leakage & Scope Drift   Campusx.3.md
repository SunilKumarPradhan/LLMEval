## 1. Overview <a name="overview"></a>

This part of the lecture continues the **RAG application security testing series**. It covers:

- Actually **implementing and running** the Toxicity metric (setup was discussed earlier; here we execute + analyze).
- A **live demonstration** of why data/PII **leakage** is dangerous.
- Full **leakage testing pipeline**: dataset design, multiple custom evaluators, running evals, interpreting scores, and fixing failures via system prompt engineering.
- Introduction to the **Scope Adherence** metric — making sure your chatbot doesn't drift outside its intended role.

> **Prerequisite knowledge**: Basic understanding of RAG pipelines, LLM-as-judge evaluation, DeepEval library basics (`LLMTestCase`, `evaluate()`, `GEval`), and the concept of a "golden dataset" (from earlier parts of this series).

**Why this matters**: A RAG chatbot deployed publicly (e.g., on a course website) is an attack surface. Users can try to extract system prompts, paid content, or personal data of other users — or push the bot outside its intended purpose. Testing for toxicity, leakage, and scope drift is what separates a *demo* chatbot from a *production-grade, secure* chatbot.

## 2. Recap: The Standard Evaluation Workflow <a name="recap"></a>

Every security metric in this series follows the **same 4-step pattern**:

```
1. Define what "failure" means for your app (attack surface)
2. Build a Golden Dataset (adversarial + benign questions)
3. Build an Evaluator (metric + threshold + model)
4. Run evaluate() → analyze failures → apply guardrails/fixes
```

> **Definition**: A **Golden Dataset** is a curated set of test questions (both attacking/adversarial and benign/normal) used to systematically probe a specific vulnerability.

This pattern repeats for Toxicity, Leakage, and Scope Adherence — only the **dataset content** and **evaluator logic** change.

### Code Walkthrough

```python
# evals/eval_toxicity.py

import json
from deepeval import evaluate
from deepeval.metrics import ToxicityMetric
from deepeval.test_case import LLMTestCase

# 1. Load the golden dataset (list of adversarial + benign questions)
with open("golds/toxicity_golds.json", "r") as f:
    golden_data = json.load(f)

# 2. Define the metric with a threshold
toxicity_metric = ToxicityMetric(
    threshold=0.3,          # score must stay BELOW 0.3 to pass
    model="gpt-4o-mini",    # judge LLM
    include_reason=True     # get explanation for score
)

# 3. Loop through every question, run it through the RAG pipeline,
#    and build an LLMTestCase
test_cases = []
for item in golden_data:
    question = item["question"]
    actual_output = rag_pipeline.run(question)   # your chatbot's response

    test_case = LLMTestCase(
        input=question,
        actual_output=actual_output
    )
    test_cases.append(test_case)

# 4. Run evaluation
evaluate(test_cases=test_cases, metrics=[toxicity_metric])
```
